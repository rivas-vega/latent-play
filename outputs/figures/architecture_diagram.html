B. Dónde se aplica SIGReg y Cómo predice g_ψ
★ AQUÍ SE APLICA SIGReg + VICReg (sobre z_t) Anti-Colapso

Se toma el promedio espacial z̄_t ∈ ℝ^192 del Online Encoder f_θ en el batch:

  • SIGReg (λ=0.05): Proyecta z̄_t en M=64 direcciones aleatorias 1D (u^(m) ∈ S^191) y aplica el test de normalidad de Epps-Pulley para forzar z̄_t ~ N(0, I).
  • VICReg Hinge (λ=0.05): Fuerza desviación estándar Std(z̄_t) ≥ 1.0 en cada dimensión.
Predictor Causal Espaciotemporal g_ψ(z_0..t, e(k_0..t))

2 bloques STBlock (atención espacial sobre los 64 parches + atención causal temporal) predicen el cambio residual:

ẑ_{t+1} = z_t + Δz_t = z_t + g_ψ(z_{0..t}, E_a(k_{0..t}))

¿Qué se embebe exactamente en el modelo?
1. Imágenes RGB → 64 Tokens Espaciales (PatchEmbed):

Cada frame x_t ∈ [0,1]^(3×64×64) pasa por una convolución Conv2d(3 → D, kernel=8×8, stride=8×8). Esto divide la imagen de 64×64 en una cuadrícula de 8×8 = 64 parches (cada parche cubre 8×8 píxeles) y proyecta cada parche a un vector de dimensión D=192. Se le suma un embedding posicional aprendible P_spatial ∈ ℝ^(64×192).

2. Acciones Discretas → Vector de Condicionamiento (Action Embed E_a):

El índice discreto k_t ∈ {0,1,..,7} descubierto por el LAM se busca en una tabla nn.Embedding(8, 192), obteniendo un vector e(k_t) ∈ ℝ^192. En el predictor JEPA, este vector se suma (broadcast) a los 64 tokens espaciales del frame t: h_t[p] = z_t[p] + e(k_t).

Etapa 1: Cómo descubre acciones el LAM (Sin Etiquetas)
1. Codificador Inverso (IDM): Toma la secuencia x_{0..T-1}, aplica PatchEmbed + 3 bloques STBlock → obtiene h_t. Calcula la diferencia temporal Δh_t = h_{t+1} - h_t y aplica un Spatial Attention Pool sobre los 64 parches para concentrarse en lo que se movió → vector continuo u_t ∈ ℝ^16.
2. Cuantización Vectorial Coseno (Cosine VQ, K=8): Normaliza en esfera unitaria (L2-norm) y asigna el código más cercano k_t = argmin_k ||û_t - ĉ_k||_2. Incluye regularización de entropía de batch para usar los 8 códigos uniformemente (8/8 activos).
3. Decodificador Forward (FDM): Toma únicamente el frame actual x_t + el código cuantizado z_q(k_t) y predice el cambio de píxeles x̂_{t+1} = x_t + Δx̂_t ponderando por movimiento (w = 1 + 5|x_{t+1} - x_t|).
Loop Externo (Físico / MPC en el Juego) 1 paso por frame t
  1. Observación actual y Meta: El agente recibe el frame actual x_t y tiene la imagen destino x_goal.
  2. Codificación al espacio JEPA: Ambos se codifican con f_θ:
    z_t = f_θ(x_t), z_goal = f_θ(x_goal)
  3. Llamada al Loop Mental (CEM): El planificador mental devuelve el mejor primer código latente k_0* ∈ {0..7}.
  4. Traducción a Acción Real (ActionAlignment φ): El MLP ligero traduce (k_0*, z̄_t) al botón real del juego corrigiendo el sesgo de frecuencia:
    â_t = argmax_a [ log P_φ(a | k_0*, z̄_t) - 0.5·log P(a) ]
  5. Ejecución y Realimentación: Se ejecuta â_t en Crafter, el entorno devuelve x_{t+1} y el ciclo se repite.
Loop Interno Mental: Planificación CEM en Espacio Latente 4 iteraciones × 128 futuros

Ocurre 100% dentro de la cabeza del agente (sin tocar el simulador del juego ni reconstruir píxeles):

Paso 1: Muestrear 128 Planes

De una distribución categórica P^(i) ∈ Δ^8 para cada paso del horizonte H=6, muestrea M=128 secuencias candidatas de códigos latentes: k^(m) = (k_0, k_1, ..., k_5) ∈ {0..7}^6.

Paso 2: Imaginar Rollout en JEPA

Para los 128 planes en paralelo (en GPU), el predictor g_ψ encadena 6 pasos hacia el futuro partiendo de ẑ_0 = z_t:
ẑ_{h+1}^(m) = ẑ_h^(m) + g_ψ(ẑ_{0..h}^(m), E_a(k_{0..h}^(m)))

Paso 3: Evaluar Coste a la Meta

Compara el estado final imaginado ẑ_6^(m) contra el estado meta z_goal usando distancia L1 en el espacio latente:
Coste^(m) = ||ẑ_6^(m) - z_goal||_1

Paso 4: Refinar Élites (Top-16)

Selecciona los E=16 planes con menor coste, actualiza las probabilidades P^(i+1) hacia esos élites, y tras I=4 iteraciones entrega k_0* = argmax P_0^(4) al Loop Externo.
